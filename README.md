# G-Phenome

**A pretrained GWAS foundation model for amortized fine-mapping.**

GWAS summary statistics in → causal variant prioritization scores out. In seconds. No LD reference needed.

## What it does

G-Phenome takes any GWAS summary statistics file and outputs a causal prioritization score (0–1) for every variant — a neural network trained to approximate SuSiE fine-mapping posteriors. Higher scores indicate stronger evidence for causal involvement at the locus.

```bash
python inference/predict.py my_gwas.tsv my_results.scores.tsv
```

**Input:** Standard GWAS summary statistics (chromosome, position, rsID, beta, SE, p-value, MAF).

**Output:** Per-variant causal prioritization scores (0–1) with rsIDs. Ready for gene prioritization, locus triage, or downstream atlas analysis.

## Key results

| Metric | G-Phenome | p-value baseline |
|--------|---------|-----------------|
| AUROC vs SuSiE (PIP > 0.5) | **0.878** | 0.775 |
| AUPRC vs SuSiE (PIP > 0.5) | **0.106** | 0.030 |
| AUROC vs SuSiE (PIP > 0.1) | **0.886** | 0.736 |
| AUPRC vs SuSiE (PIP > 0.1) | **0.293** | 0.090 |

- **88% agreement with SuSiE** on 2,059 held-out GWAS (full test set)
- **83-92% agreement** with FINEMAP, PAINTOR, CAVIARBF, ABF, PolyFun (trained on SuSiE only — transfers across methods)
- **Pretraining gap: +0.147 AUROC / 5.3× AUPRC** (pretrained 0.878 vs random 0.731)
- **Full GWAS in 16.0 seconds** end-to-end on GPU (10.9M variants, custom CUDA kernel)
- **Per locus in 129 ms** (65K variants, HLA region)
- **3.3 MB** total model size. **525 MB GPU memory.**
- **Top 5% of G-Phenome-ranked variants recover 63% of SuSiE high-confidence variants** (vs 29% for p-value)

## Quick start

```bash
# Install dependencies
pip install torch numpy pandas scikit-learn

# Recommended for maximum speed:
pip install polars cupy-cuda12x   # ~50× faster CSV reading + CUDA LD kernel

# Run on your GWAS
python inference/predict.py your_gwas.tsv output.scores.tsv

# Run on a specific locus
python inference/predict.py your_gwas.tsv output.scores.tsv --region chr6:25000000-35000000

# That's it.
```

No R. No LD reference panel. No setup.

**Benchmarked speed** (10.9M variant GWAS):
- GPU + CuPy + polars: **16.0 seconds** end-to-end (5.1s GPU, 6.7s read, 4.2s prep)

**Memory**: ~525 MB GPU allocated, ~261 MB CPU feature array. Model is 3.3 MB.

## How it works

1. **Pretrained encoder** (811K params): Self-supervised transformer trained on 31,200 GWAS from the EBI GWAS Catalog. Learns cross-GWAS variant patterns via masked z-score reconstruction + denoising.

2. **Fine-mapping head** (17K params): Small prediction head trained on 8,232 CAUSALdb2 GWAS with real SuSiE posterior inclusion probabilities. Encoder frozen during head training.

3. **Inference**: Raw GWAS → 500kb blocks → encoder → head → per-variant scores with rsIDs. No LD matrix computation. Custom CUDA kernel for LD feature acceleration.

## Reproduce everything

```bash
# Full pipeline: prepare data → pretrain encoder → train head → run all benchmarks
bash reproduce.sh

# Or skip training (models included) and just run benchmarks
# (reproduce.sh auto-detects existing models)
bash reproduce.sh
```

Core model benchmarks are reproduced by `eval/benchmark.py`. Downstream atlas analyses are reproduced by `atlas_exploration_final/run_atlas_exploration.py`.

The downstream atlas starts from `atlas_exploration_final/inputs/no_window_gatlas_1587_gwas.parquet`, a fixed score-atlas table generated by applying G-Phenome across `1,587` GWAS and aggregating per-variant scores across studies. The public file name preserves the original run label; the scientific object is the `1,587`-GWAS score atlas. Its columns are `CHR`, `BP`, `snp`, `n_traits`, `traits`, `scores`, `max_score`, and `mean_score`. This table is the handoff from model inference to the atlas analysis.

Full retraining requires the preprocessed `data/gwas_31k/*.npz` corpus (`31,200` EBI GWAS, about `42 GB`). The raw harmonized EBI GWAS files are not required for normal reproduction once this preprocessed corpus is present. If `data/gwas_31k` is absent, `reproduce.sh` can rebuild it from raw EBI downloads via `data/download_ebi.py` and `data/preprocess.py`, but this is much slower and substantially larger than using the frozen preprocessed corpus.

```

├── data/
```

## Data provenance

| Data | Source | Used for |
|------|--------|----------|
| 31,200 EBI GWAS | [EBI GWAS Catalog](https://www.ebi.ac.uk/gwas/) | Encoder pretraining |
| CAUSALdb2 (10,291 GWAS) | [mulinlab.org/causaldb](http://www.mulinlab.org/causaldb/) | Head training (SuSiE PIPs) |
| HM3 reference (1.15M variants) | [1000 Genomes](https://www.internationalgenome.org/) | Variant filtering |
| 16 UKBB sentinel traits | [OpenGWAS](https://gwas.mrcieu.ac.uk/) | Speed and inference stress tests |

All sentinel traits excluded from all training. 1.5% overlap between pretraining and CAUSALdb2 GWAS (self-supervised pretraining only, no label leakage).

Expected local data layout for full reproduction:

| Path | Contents | Required for |
|------|----------|--------------|
| `data/gwas_31k/*.npz` | Preprocessed 500 kb GWAS blocks from 31,200 EBI GWAS | Encoder pretraining |
| `data/causaldb/susie_pips.parquet` | HM3-filtered CAUSALdb2 SuSiE labels | PIP-head training and held-out benchmark |
| `data/causaldb/v2.1/credible_set.txt` | Full CAUSALdb2 multi-method table | Multi-method benchmark sections |
| `data/sentinel_sumstats/*.txt` | UKBB/OpenGWAS sentinel traits excluded from training | Speed benchmark |
| `data/hm3.bim` | HapMap3/1000 Genomes reference variants | Rebuilding CAUSALdb parquet from raw CAUSALdb |

The distributed model weights are sufficient for inference on new GWAS without any of these training datasets.
